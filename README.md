## 🎯 Documentation Philosophy

My approach is rooted in these principles:

**1. Clarity Through Structure**
- Use information architecture as the foundation. Organize content to match how users think and work.
- Apply DITA principles (modularity, reuse, single-sourcing) even when not working in DITA.
- Break complex ideas into smaller, digestible chunks.

**2. Accuracy Over Speed**
- Verify all technical claims against authoritative sources (official docs, code, SMEs).
- Test procedures manually before publishing.
- Own the accuracy—AI is a drafting assistant, not a replacement for judgment.

**3. Audience-Focused Writing**
- Write for the reader who has to actually complete the task, not for someone who already understands the system.
- Segment documentation by audience (end users, developers, administrators) and adapt language accordingly.
- Anticipate questions and edge cases.

**4. Responsible AI Use**
- Use generative AI tools (Claude, ChatGPT) to accelerate first-draft creation and research.
- Always verify AI-generated content against official documentation and authoritative sources.
- Apply editorial judgment: AI output is a starting point, not a finished product.
